# Alaya: design decisions

A record of what we have decided, in order. Each line is final until we change it on purpose.

| # | Question | Decision | Date |
| --- | --- | --- | --- |
| 1 | What kind of OS | Our own kernel, from scratch, booting in QEMU first, maybe a real PC later | 2026-11-19 |
| 2 | Not in scope | No website, no microcontroller, no personal content. Nothing carries over from the old spec | 2026-11-19 |
| 3 | CPU | x86-64 | 2026-11-19 |
| 4 | Language | Rust | 2026-11-19 |
| 5 | Kernel structure | Microkernel: memory, scheduling and messages in the kernel; drivers and files as separate programs | 2026-11-19 |
| 6 | Boot | Limine bootloader | 2026-11-19 |
| 7 | Security | Capabilities: a program can only use what it holds a handle to | 2026-11-19 |
| 8 | Messages | Synchronous calls with replies, plus short asynchronous notifications (seL4 style) | 2026-11-19 |
| 9 | Memory | User space decides: the kernel allocates nothing and builds its objects from raw memory capabilities that programs give it (seL4 style) | 2026-11-19 |
| 10 | Cores | Revised: designed for many cores from day one (one big kernel lock, a run queue per core, thread-safe servers); the first milestone may run on one core | 2026-11-19 |
| 11 | Scheduler | Revised: fixed priorities plus time budgets (scheduling contexts, seL4 MCS style); servers run on their caller's budget | 2026-11-19 |
| 12 | Program interface | Our own capability-based API first; the POSIX layer follows (made firm by 21, built per 31) | 2026-11-19 |
| 13 | First interface | A graphical desktop (windows and a mouse) is the goal from the start. Kernel debug output still goes to the serial port | 2026-11-19 |
| 14 | Windows | A compositor program owns the screen; each app draws its own pixels into a buffer it shares with the compositor (like Wayland) | 2026-11-19 |
| 15 | Disk format | Our own filesystem, designed for this OS | 2026-11-19 |
| 16 | Crash safety | Copy-on-write: never overwrite in place; write new blocks, then switch one root pointer. Snapshots come almost free | 2026-11-19 |
| 17 | File view | Revised by 22: one tree for the person and the trusted desktop; apps see only their own folder and their grants | 2026-11-19 |
| 18 | Open check | Revised by 22: grants, capabilities that carry what, rights and when (live, pinned, until), issued by open/save dialogs, drag and drop, and install-time requests | 2026-11-19 |
| 19 | First drivers | Revised: virtio (QEMU) first, then one real reference PC (NVMe, USB, HD Audio, network, one GPU family); each driver is its own restartable program | 2026-11-19 |
| 20 | License | Revised: GPL-3.0 for kernel, servers and drivers, plus a linking exception for the system libraries apps link against | 2026-11-19 |
| 21 | Games | Native games, Linux/Vulkan games ported through SDL, and later Windows games through a Wine/Proton-style layer. This makes the POSIX layer (decision 12) a firm requirement, sized for what Wine needs | 2026-11-19 |
| 22 | Signature feature | History and grants (`concept-history-and-grants.md`) with the storage classes from `battle-test.md`: every commit attributed to a capability, history by retention rule, per-app undo, branches, opt-in replay | 2026-11-19 |
| 23 | Reference PC | A laptop with an NVIDIA RTX 4050 and an Intel Core i7 13th gen (hybrid graphics: the Intel Iris Xe built-in GPU drives the screen, the NVIDIA GPU renders; the CPU mixes performance and efficiency cores). GPU path: a kernel-side driver using NVIDIA's GSP firmware, plus Mesa's NVK Vulkan driver (MIT) in user space | 2026-11-19 |
| 24 | Out of memory | Compress idle memory in RAM first, then ask apps to free caches, then stop the lowest-priority app. No disk swap. The foreground game and the compositor are never stopped. Each app has a memory budget | 2026-11-19 |
| 25 | Network | Open by default: every app can reach the network, as on Windows and Linux. Note: an app that was granted files can send them anywhere | 2026-11-19 |
| 26 | Kernel interface | Accepted as drafted in `kernel-interface.md`: 10 calls, everything else is a call on a capability; close to seL4 with MCS, plus huge pages, IOMMU domains and core types | 2026-11-19 |
| 27 | Leak guard | Network stays open, the ledger records every connection, and any app can be cut off. Once an app reads a file marked private, it needs the person's OK before going online. The mark spreads: an app that receives data or shared memory from a marked app is marked too | 2026-11-19 |
| 28 | Updates | Each system update installs on a branch of the store and the machine boots from it. Limine keeps an entry for the current and the previous system, and a boot counter falls back automatically if the new one fails to boot or the person rejects it | 2026-11-19 |
| 29 | Disk encryption | The whole store is encrypted (AES, using the CPU's AES instructions). The TPM releases the key after a short PIN at boot; a recovery key is shown once at setup for when the TPM or board is replaced | 2026-11-19 |
| 30 | People | Separate people: each has their own store branch of files, history, grants and encryption key (unlocked at login with their own PIN or passphrase, on top of decision 29). Apps and games are installed once and shared, read-only | 2026-11-19 |
| 31 | POSIX layer | Port musl (MIT); its Linux calls are translated to our servers. Sized for Wine: threads, futex-style waits, mmap at fixed addresses, signals (incl. crash handlers), dlopen, posix_spawn, Unix sockets that pass open handles | 2026-11-19 |
| 32 | Testing | Accepted as drafted in `test-plan.md`: TLA+ and Kani proofs of revocation, scheduler and commits; fuzzing; power-cut and driver-crash injection; hard gates on the reference laptop under full load | 2026-11-19 |
| 33 | History size | Only changed blocks are stored. Storage classes per battle test (documents full history, apps and games current plus one pre-update snapshot, caches none). Thinning: every moment for a day, hourly for a week, daily for a month, weekly after. History budget: 15 % of the disk by default, oldest pruned first. The timeline only shows this history and costs no extra space | 2026-11-19 |
| 34 | Desktop | Familiar floating windows plus a timeline to see files and the desktop as they were, and a grants badge on each window. Implementation requirements in `timeline.md`, including per-file keys so "forget" erases a file from all history | 2026-11-19 |
| 35 | Name | Alaya (ah-LAH-yah): the storehouse of memory that keeps every past impression. A full trademark check is still needed before public use | 2026-11-19 |
| 36 | Backup | Each person's store and its history stream, encrypted end to end, to an external drive or another Alaya machine, and optionally to cloud storage the person chooses (any S3-compatible or WebDAV service; Alaya runs no service of its own). Incremental by commit. Keys never leave the machine, so restoring needs the recovery key. "Forget" also makes the file unreadable in every backup, because its key is gone. Runs on a background budget and pauses on battery or metered networks | 2026-11-19 |
| 37 | Apps | Signed bundles from any source, no gatekeeper. A bundle's manifest lists the grants it asks for at install (folders, camera, microphone, game controllers). Updates must be signed by the same developer key. Installs and updates happen on a branch the person approves; apps are installed once, read-only, shared by all people. A per-person developer mode allows unsigned builds, with a clear warning | 2026-11-19 |
| 38 | Clipboard | Classic (confirmed: desktop-only judged safe but not useful): any app can read the clipboard at any time. To keep decision 27 whole, clipboard content copied from a marked (private) app carries the mark, and an app that reads it is marked too; every clipboard read is recorded in the ledger | 2026-11-19 |
| 39 | Search | The desktop indexes each person's files and their history; picking a result hands that file to an app as a grant, and saved searches can be granted like folders. The index is encrypted with the person's key, built on a background budget, never shows private files to anyone but their owner, and "forget" removes a file from it | 2026-11-19 |
| 40 | Terminal | Full access: commands run in the terminal see the person's whole tree, like Linux. Limits that still hold: only that person's own files (never another person's); every change is attributed and undoable through history; reading private files still triggers the leak guard. Risk accepted: a script run in the terminal can touch any of the person's files | 2026-11-19 |
| 41 | SDK | Written in Rust, the primary path for apps, with a stable versioned C interface so C, C++ (game engines), Zig, Go and others can use it | 2026-11-19 |
| 42 | Accessibility and languages | Built in from the start: the UI toolkit carries an accessibility tree (screen reader, full keyboard use, scaling, high contrast) and all text is UTF-8 and translatable, including right-to-left scripts, from the first desktop (milestone 6) | 2026-11-19 |
| 43 | Recovery | Both: a small read-only recovery system on the disk (opened by a key at boot or after 3 failed boots) that can roll back to any past system, repair the store, restore from backup or reset; plus an optional recovery USB stick for a dead disk. Recovery needs the PIN or the recovery key to touch data; reset erases by destroying the keys | 2026-11-19 |
| 44 | Crash reports | Every crash is saved locally as a readable report; nothing is sent unless the person reviews it and chooses to. Reports never include file contents or names of private files. App crashes go to the address the app's manifest names; system crashes to the Alaya project. A kernel crash is saved to a reserved area and shown at the next boot | 2026-11-19 |
| 45 | Power and heat | Automatic: full speed plugged in, balanced on battery. A thermal governor reads the CPU and GPU temperatures and lowers time budgets and clocks smoothly before the hardware's own throttling starts, so frame times stay steady rather than spiking. Per-game overrides (for example a frame cap on battery) | 2026-11-19 |
| 46 | Background apps | An app with no visible window is frozen (no CPU) unless it holds a background grant (music, downloads, chat). Notifications need a grant too, go through the desktop, and are silenced during full-screen games | 2026-11-19 |
| 47 | Clocks (proposed, not objected to) | History is ordered by a commit counter that only goes up, never by the wall clock, so a wrong or changed clock cannot scramble the timeline; wall-clock times are only labels. Time is set from the hardware clock and kept by authenticated network time (NTS) | 2026-11-19 |
| 48 | Displays | Full modern displays from the first versions: several monitors with hotplug, per-monitor scaling (fractional, mixed DPI), high refresh rates, variable refresh rate, HDR with colour management, and the laptop's built-in panel plus external screens on the reference laptop | 2026-11-19 |
| 49 | Peripherals | Bluetooth first (wireless game controllers, headsets with low-latency audio, mice and keyboards), as its own restartable driver and server; pairing a device is a desktop action, and an app reaches a device only through a grant. Printing and scanning come later, driverless only (IPP Everywhere / eSCL), so no vendor drivers are needed | 2026-11-19 |
| 50 | Input methods | A built-in input-method server sits between the keyboard and apps: keyboard layouts, dead keys, composing scripts (Chinese, Japanese, Korean and others), emoji and on-screen keyboard, in every app from the first desktop. Only the focused window receives keys; apps never read the keyboard directly | 2026-11-19 |
| 51 | Object lifetime | Dropping the last handle to a kernel object frees nothing; its memory comes back only when the untyped it was made from is revoked (no seL4 zombies). Each program has one flat handle table. A revoke in progress always deletes faster than other cores can copy, so it always finishes | 2026-11-19 |
| 52 | Linux compatibility (for Claude Code) | Two parts. Now: Claude Code runs on the host PC and drives Alaya in QEMU (build, serial log, GDB stub, QEMU control socket). Inside Alaya: grow the POSIX layer (31) until Node.js, bash, git, ripgrep and basic command-line tools are recompiled for Alaya, and run Claude Code's JavaScript bundle on that Node. The POSIX layer gains `fork` (needed by bash), Linux-style `epoll`, `eventfd`, `timerfd` and `inotify` (so ports need few patches), pseudo-terminals, and the right to make writable-then-executable memory for JIT engines. Lands in milestone 8b, before the first boot on real hardware; USB networking comes in milestone 11 so it reaches the internet before Wi-Fi exists (user chose this over a Linux system-call personality and a Linux VM). `fork` approved with the child holding exactly the parent's grants. Rules in `linux-compat.md` section 7; where Alaya's versions go beyond Linux (process families in the ledger, file watching from the commit stream, sessions on a branch) in section 8 | 2026-11-19 |
| 53 | Time budgets refill | Sporadic refills, as in seL4 MCS: time used in one stretch starting at s comes back one period after s, so a thread never runs more than its budget in any window of one period (user confirmed my recommendation) | 2026-11-19 |
| 54 | Core placement | The kernel places threads: a scheduling context names a core type (any, performance, efficiency) and optionally one core; when a thread wakes the kernel picks an idle core of that type, else the one running the least important work; idle cores pull waiting work. Running threads are never moved (user chose this over pinned scheduling contexts with a user-space placement service) | 2026-11-19 |
| 55 | Budget runs out in a server | A server running on its caller's budget that runs out waits for the caller's next refill; the slow caller pays for itself. Timeout messages to a handler can be added later (milestone 4) without changing this | 2026-11-19 |
| 56 | Address spaces | Arrive in milestone 3. Each address space is given an untyped of its own, and the kernel takes page tables from it as mappings need them, so the kernel still allocates nothing and programs only map pages | 2026-11-19 |

The rules attached to the other decisions are in `battle-test.md` and are part of them.
